AI도 암기와 사고를 나눠야 할까? DeepSeek Engram

익숙한 패턴까지 매번 계산해야 할까. 계산할 것과 찾아올 것을 나누는 조건부 메모리를 살펴본다.

윤동현2026.10.29Engram · Conditional Memory · MoE

구구단을 쓸 때마다 덧셈부터 다시 시작하지는 않는다. 익숙한 결과는 꺼내 쓰고, 계산이 필요한 부분에 시간을 쓴다. AI 모델에도 이런 역할 분담을 설계할 수 있을까? 이 비유를 출발점으로 Engram을 읽어보자. 사람의 기억과 모델의 메커니즘이 같다는 뜻은 아니다.

1. 한 문장으로 이해하는 Engram

Engram은 학습한 N-gram 임베딩을 조회해 Transformer를 보완하는 조건부 메모리 모듈이다. 베이징대·DeepSeek 연구진이 2026년 1월 12일 공개했다. 이 글의 수치는 개정판 v2의 본문 표를 기준으로 한다. 논문과 공개 이력

2. 어떤 문제를 바꾸려는가

연구진의 가설은 익숙한 지역 패턴을 재구성하는 계산 일부를 조회로 넘기면, 복잡한 추론에 모델의 표현 능력을 더 쓸 수 있다는 것이다. MoE의 조건부 계산과 Engram의 조건부 메모리를 결합한다. §1

공부할 질문은 “더 큰 모델인가?”에서 한 걸음 더 간다. 같은 자원을 무엇을 계산하고 무엇을 저장하는 데 배분할 것인가?

3. 입력에서 메모리를 읽는 과정

N-gram은 연속된 N개 토큰의 묶음이다. Engram은 토큰 ID를 정규화한 뒤, 여러 해시로 메모리를 조회한다. 현재 은닉 상태를 이용한 게이트가 조회 벡터의 반영량을 조절하고, 짧은 convolution을 거쳐 본체에 합친다. §2

4. 결과는 비교 조건과 함께 읽기

이 표를 볼 때는 “메모리를 붙이니 좋아졌다”와 “다른 방식으로 같은 자원을 배분하니 좋아졌다”를 구별해야 한다. 후자가 이 비교에서 살펴볼 질문이다. 특정 벤치마크의 개선이 모든 실제 업무의 개선을 보장하지도 않는다.

5. GPU 밖에 두면 공짜일까

조회 주소를 미리 알 수 있어 호스트 메모리에서 prefetch할 수 있다. Table 4는 H800·512개 시퀀스 조건에서 100B 테이블 offload의 처리량 감소가 최대 약 2.8%였다고 보고한다. O(1) 조회가 전송 시간까지 없앤다는 뜻은 아니다. §6.4

6. RAG, 대화 기억, Mamba와 나란히 보기

“기억”이라는 단어만으로 기술을 묶으면 무엇을 저장하고 읽는지가 흐려진다. 원리의 위치를 기준으로 비교해 보자.

  • Engram: 학습된 임베딩을 읽는 모델 구성 요소다. 사용자의 지난 대화를 자동 보관하는 기능으로 해석하면 안 된다.
  • RAG: 원 논문은 검색기로 위키피디아 문서 구절을 찾아 생성에 활용한다. 문서 검색과 모델 내부 임베딩 조회는 다른 설계다. RAG 원 논문
  • Mamba: 입력에 따라 상태를 갱신하는 시퀀스 모델이다. 앞선 Mamba 글과 비교할 때는 현재 시퀀스의 상태와 학습된 패턴 테이블을 구별하면 좋다. Mamba 원 논문

이들은 같은 문제의 점수표에서 승자를 고르는 세 후보가 아니다. 문서를 제공할지, 과거 입력을 상태에 압축할지, 학습된 패턴을 읽을지처럼 서로 다른 설계 질문에 놓여 있다.

7. 다음에 직접 확인할 것

이 글의 해석은 “암기와 사고의 완전한 분리”보다 계산과 저장에 자원을 어떻게 나눌지에 가깝다. 다음 공부에서는 아래 질문을 확인해 보고 싶다.

  • 메모리 용량을 늘릴 때 품질과 지연 시간은 각각 어떻게 바뀔까?
  • 같은 토큰 묶음도 문맥이 달라지면 게이트 값이 달라질까?
  • 한국어 토큰 분할 방식에서도 비슷한 이점을 얻을까?
  • 개인 장비에서 재현하려면 RAM·전송 대역폭·배치 크기를 어떻게 통제해야 할까?

공식 저장소의 데모는 데이터 흐름을 이해하기 위한 코드다. Attention·MoE 등 일부 구성 요소를 모사하므로, 데모 실행을 논문의 학습·성능 재현으로 볼 수는 없다.
